# GitHub Blockage Research

> GitHub 网络可达性与封锁状况的实证研究
> 环境：授权沙盒（家庭网络模拟）| 日期：2026-08-12 | 许可：MIT

## 项目简介

本仓库沉淀一次完整的**网络封锁测绘研究**：通过官方 IP 基准、DNS 交叉验证、传输层实测与高频时序监测，量化 GitHub 生态各域名/IP 在真实网络环境下的可达性分布，并归纳出可预测的**动态封锁规律**，为自动化任务设计重试与绕行策略提供数据支撑。

**方法一句话**：DNS 拿真值 → 握手验身份 → 传输判封锁 → 时序找规律 → 对照验机制。

## 核心规律

### 1. 三层封锁结构

| 层级 | 对象 | 实测可用率 | 特征 |
|---|---|---|---|
| 🟢 稳定可用 | `api.github.com` 亚太节点 (`20.205.243.168`) | **100%** | 全程无封锁窗口 |
| 🟡 间歇封锁 | `github.com` 主站节点、`raw.githubusercontent.com` | 28–61% | 封禁/解封循环 |
| 🔴 持久封锁 | `140.82.121.x` 段、`gist.github.com` | **0%** | 全程不可达 |

### 2. 窗口参数（时序监测 21 轮实测）

```
封禁期   3–5 分钟（样本：1/3/4/4/5 分钟）
解封期   4–12 分钟
主站节点同步率   71%（域名级规则 + 边界 1–2 轮漂移）
跨域名同步       独立（raw 与 github.com 窗口不同步）
```

### 3. 封锁粒度与触发机制

- **IP 级**：同段 `.166` 封锁时 `.168` 正常（20.205.243.x）
- **域名/SNI 级**：gist 在所有可用 IP 上均 0 字节
- **非探测触发**：对照实验（停止探测 3 分钟状态不变）证明封锁由**外部时间驱动规则**产生；同频探测的 api 节点全程未被封锁，排除频率因素

### 4. DNS 污染（gist 专属）

本地解析被投毒至**轮换的不可达 IP 池**（≥5 个：`78.16.49.15` 长驻 / `159.24.3.173` / `37.61.54.158` / `243.185.187.39` 等），与传输封锁双重叠加；其余域名 DNS 正常解析至官方节点。

### 5. 工程结论（重试策略）

| 场景 | 策略 |
|---|---|
| API 自动化 | 固定走亚太 api，无需重试 |
| git clone / 主站 | 60s 间隔重试（封锁窗 3–5 分钟自动解除） |
| raw 文件下载 | 失败后等待 5–10 分钟重试 |
| 140.82.121.x / gist | 视为永久不可用，直接绕行 |

## 方法论

### 阶段流程

1. **官方 IP 基准** — 从 `api.github.com/meta` 等 meta 端点获取官方 IP/CIDR，作为判定"污染"的准绳
2. **DNS 交叉验证** — 系统 DNS / 公共 DNS / TCP 53 / DoH 四层对比；DoH（如 `dns.lemdns.com`）是劫持环境下的真值来源
3. **TCP 连通性** — 多线程批量探测（可达/超时/拒绝/重置分类）
4. **TLS 证书身份验证** — 区分真服务、中间人与 mTLS
5. **传输层实测**（判定核心）— `--resolve` 强制指定 IP 做真实 HTTPS 请求；**TCP/TLS 握手通过不代表可用，0 字节 = 传输层封锁**
6. **限速对照** — 同时测国内源，区分"环境带宽限制"与"目标限速"
7. **功能级验证** — git clone / SSH 全握手实测（smart HTTP 单连接可绕开 raw 封锁）
8. **时序分析**（动态封锁）— 20s 间隔多节点采样 ≥20 分钟 → 可用率分层 / 窗口时长分布 / 同步性分析
9. **对照实验** — 停止探测 3–5 分钟，判定封锁是外部规则还是探测触发
10. **报告输出** — 矩阵 + 证据链 + 复测命令

### 关键教训

- 不要把"慢"当封锁（对照组是刚需）
- 不要把解析结果当污染（先核对官方列表，`20.205.243.x` 就是官方节点）
- 单次测量只是快照，动态封锁必须看时间线

## 快速开始

```bash
# 1. 批量 TCP 连通性测试
python3 connectivity_probe.py 140.82.112.3 140.82.121.3 --ports 443

# 2. 封锁判定（传输层实测，0 字节 = 封锁）
curl -s --resolve github.com:443:20.205.243.166 -m 10 \
  -o /dev/null -w '%{http_code} %{size_download}' https://github.com/

# 3. DoH 真值（DNS 劫持环境下的可靠解析）
curl -s -H "accept: application/dns-json" \
  "https://dns.lemdns.com/dns-query?name=gist.github.com&type=A"

# 4. 动态封锁时序监测（20s 间隔 × 45 轮 ≈ 15 分钟）
python3 blockage_monitor.py 20 45 monitor.csv
```
